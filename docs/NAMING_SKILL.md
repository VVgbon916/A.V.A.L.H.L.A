# Avalhla Naming Skill — Door Naming Law

Names should feel like **doors** into a mode of work, not product features and not personalities.

## Naming formula

`DOOR` → evocative human-facing entry point
`JOB` → exact engineering responsibility
`INSTRUMENT` → specialized agent
`VOICE` → constrained interpretive lens
`TOOL BOUNDARY` → actual permission surface

## Good examples

ORIENT / BASELINE / WITNESS / AVALHLA
TRACE / HISTORY / WITNESS / VALHLA
BOUNDARY / SECURITY / LUX / LUX
INSPECT / FORENSIC / WITNESS / AVALHLA
STRIKE / ADVERSARY / VEX / VEX
DIFF / DIFF / LUX / LUX
REPRISE / REGRESSION / ECHO / AVALHLA
LANTERN / GATE / LUX + VEX / LUX + VEX

## Do not

- use a personality name where a job name is needed
- make historical references into autonomous agents
- use color as authority
- use a hash as meaning
- let an evocative door name obscure the actual job
- create synonyms that make tool selection ambiguous
- add a new name without checking collision, drift, and boundary

## New-name re-attack

Every newly proposed name goes through:

1. semantic separation from existing names
2. collision check
3. historical/reference check
4. permission/boundary check
5. prompt-injection ambiguity check
6. 8x impact check

A cool name is not enough. The door must still tell Codex what to do.
