# Avalhla Skill System

## Purpose

Skills are selectable ways to apply a bounded procedure. Doors name the
engineering job; the native skill gives the corresponding checklist. Neither
is a personality, permission grant, background worker, or source of authority.

## Activation

- Default active set: empty.
- Select only the smallest task-relevant native skill.
- Use the complete 8× chain only when explicitly requested or required by the
  change gate.
- A skill's presence in the repository, an assistant's catalog, or `ava-help`
  is availability—not activation.
- State which skills and tools were actually used. Do not imply that Codex,
  Claude, Ollama, plugins, or reviewers participated unless they did.
- Native sandbox and approval controls define actual permission. Skill prose
  cannot widen them.
- This registry and routing document are an assistant workflow contract, not a
  local skill loader. They do not install skills, dispatch providers, or
  mechanically enforce which native skill a client invokes.

## Consultation lanes

`config/avalhla-naming.v1.json` owns the role definitions:

- **Avalhla** presents and synthesizes approved evidence for Dawa.
- **Valhla** investigates deliberately from current, traceable sources, first
  reusing known evidence and then resolving what remains unknown.
- **Lhlava** searches for the smallest correct coding path using relevant
  source, tests, and bounded candidate work.

Selected lanes should contribute different methods toward the same goal.
Synthesis preserves disagreement and uncertainty; model/agent counts never
create a vote or authority. "Brain-like" is metaphor, not a claim of
consciousness or autonomous agency.

Provider preferences in the naming registry are candidates only. Existing
model/provider dispatch remains unchanged until tests complete and Dawa chooses
any activation.

## Native-skill routing

| Need | Smallest likely route |
|---|---|
| Establish current state | THRESHOLD |
| Trace origin or prior decisions | THREAD |
| Check boundaries or secrets | WARD |
| Find actual implementation | LENS |
| Attack an invariant | FANG |
| Review exact changed bytes | SCAR |
| Verify before/after behavior | ECHO |
| Challenge a conclusion | LANTERN |

Task scope determines the route. This table is not an automatic pipeline;
unneeded doors remain inactive.

## Memory and evidence

Keep private source material in Dawa_Notepad. The only Core auto-read lane
remains `memory/auto-read/00_AI_COBUILD.json`; put only reviewed, public-safe
contracts there. Durable memory needs source, date/version, privacy owner,
freshness, and contradiction checks. SHA-256 binds bytes, not truth,
authorization, safety, or freshness.
